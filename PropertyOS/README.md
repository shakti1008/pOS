# PropertyOS

**Collect rent. Beautifully.**

A complete offline-first property management app for Indian landlords and property managers.  
Static front-end + Supabase, built with esbuild into `dist/`. Installable as a PWA.

---

## What it does

- **Properties & units** — manage buildings, floors and individual units
- **Tenants & leases** — onboarding, renewals, end-of-lease
- **Rent collection** — status, overdue, statements, cash-flow charts
- **UPI & QR** — any UPI handle, GPay / PhonePe / Paytm links, rent posters, WhatsApp reminders
- **Public receipts** — shareable, QR-verifiable rent receipts anyone can open
- **Public listings** — publish vacancies and receive inquiries
- **Security deposits** — collect, deduct, refund with a full ledger and settlement statement
- **Utility bills** — electricity, water, gas, internet, maintenance (with optional meter readings)
- **Agreements** — plain-English lease templates with on-screen e-signatures
- **Wallet** — a rent pass for every active lease; tap the stack to fan it out, tap a pass to flip it to its UPI QR; pick a finish colour per pass
- **Reminders queue** — send overdue and due rent reminders one at a time; WhatsApp opens as a draft you review, nothing is sent automatically
- **Ledger** — payments, expenses, deposits and charges in one list with CSV export, duplicate-payment flags, and a bank-statement CSV comparison (kept on your device, never uploaded)
- **Hide balances** — blur money figures with one tap (eye button in the header or Settings)
- **Reports** — 12-month cash flow, occupancy, collection rate, profit by property
- **Team** — invite members and remove access (owners)
- **Repairs** — tenant requests and status tracking
- **Expenses & profit** — per-property tracking and insights
- **Appearance & brand** — themes, palettes, wallpapers, your own logo and name everywhere
- **Cinematic entrance** — animated landing, split-screen sign-in / sign-up, guided onboarding, sound & confetti
- **Offline-ready** — works without a connection, instant open from cache

## Setup

### 1. Database
Create a Supabase project. In the SQL editor run every file in `supabase/migrations/` **in order** (001 → 013).

### 2. Config
`config.js` is already filled with a working demo Supabase project so you can try the app immediately.

To use your own project, replace the values:

```js
window.PROPERTYOS_CONFIG = {
  url: "https://YOUR_PROJECT.supabase.co",
  anonKey: "YOUR_ANON_KEY"
};
```

Then run all migrations (001 → 013) in your Supabase SQL editor.

`config.js` is copied into `dist/` unchanged. It is never hashed and never cached long-term, so you can edit it directly, either in the project before building or in `dist/config.js` on the host.

### 3. Install, build, deploy
Requires Node 20 or newer.

```bash
npm ci            # install the pinned dependencies
npm run build     # write the deployable site to dist/
npm run check     # optional: verify dist/ (URLs, script order, precache list, syntax)
```

Deploy the **`dist/`** folder:

- **Cloudflare Pages**: build command `npm run build`, output directory `dist`. The build copies `_headers` into `dist/`, so Pages applies it automatically.
- **Vercel**: `vercel.json` already sets the install command, build command (`npm run build`), output directory (`dist`) and headers.
- Any other static host: upload `dist/` and apply the cache rules from `_headers`.

Local work:

- `npm run dev` builds, rebuilds on every change and serves `dist/` at http://localhost:3000.
- `npm run preview` serves the existing `dist/` at http://localhost:4173.

Both apply `_headers`, so the CSP and cache rules match production.

## Install as a web app

PropertyOS is a Progressive Web App (PWA). After you open it once in the browser:

**Phone (Android / Chrome)**  
Tap the browser menu → **Install app** or **Add to Home screen**.

**iPhone (Safari)**  
Share → **Add to Home Screen**.

**Desktop (Chrome / Edge)**  
Click the install icon in the address bar, or Menu → **Install PropertyOS**.

Once installed it opens full-screen, works offline, and appears like a native app.

## Security notes

- Public receipts prefer a random token (`?receipt=…`). Older QR codes that used `?verify=<charge-id>` still work for compatibility.
- Team removal uses the `revoke_membership` database function (owners only).
- The Supabase client library is bundled at build time from the pinned `@supabase/supabase-js` (see `src/supabase-bridge.js`); no CDN is used at runtime. It is pinned to 2.95.0, the version that was previously vendored. To upgrade, change the version in `package.json`, run `npm install`, and retest sign-in, payments and realtime.
- Do not put real tenant data into a demo Supabase project you do not control. Create your own project and run migrations 001–013.

## Liquid Glass v2 (visual and experience upgrade)

The app now has a final visual layer on top of the original styles.

- `css/liquid.css` is loaded last and scoped under `html.lq`. It holds the tokens, the glass-ribbon wallpaper (inline SVG, no image files), the glass material with rim light, the floating tab bar with its sliding lens, buttons, chips, badges, row icons, sheets and forms, the Home dashboard, the More launcher and the desktop sidebar.
- `js/modules/15-liquid-premium.js` runs after the other modules. It replaces the six stacked Home wrappers with one dashboard (collection beam, needs-attention list, KPI tiles, cash-flow chart, occupancy, activity), gives Rent and Leases rows an action bar underneath, rebuilds Deposits, Utilities, Agreements and Reports, adds the launcher-style More sheet and the grouped desktop sidebar, removes duplicate screen titles, and shows a glass confirm sheet instead of the browser `confirm()` when removing team members.
- To switch the layer off, remove `class="lq"` from `<html>` in `index.html`. The original look is unchanged underneath.
- Destructive sheets (labels starting with End, Delete, Remove or Reverse) use the red button automatically.
- The Apple logo in `assets/` is a placeholder. Replace `logo.png`, `logo.svg` and the icon files before deployment. Layout does not depend on the logo's proportions.
- Releases bust caches automatically. Every build content-hashes the scripts and stylesheets in `dist/build/` and names the service-worker cache after a hash of the whole file list, so installed apps pick up a new release on their next update check. There is nothing to bump by hand.
- Files in `assets/` are not hashed but are cached for a year (`_headers`, `vercel.json`). To change one, give the new file a new name and update where it is referenced.
